# SPIKE Prime 最強ライントレーサー "LINE RACER"

LEGO SPIKE Prime（基本セット 45678 + 拡張セット 45681）で作る、
**無限周回ライントレースのベストタイム記録機**。

**フィールド**: 白いフィールド上に、ランダムな曲線が一周した黒いラインが引かれている。
障害物・ミッションはなし。いかに速く正確にラインを周回し続けるかだけを競う。

- 起動時の**自動セットアップ**（配線チェック・ジャイロキャリブレーション・符号自動判定）
- 1周目: エクスプローララン（中速で完走し、コースを「記憶」）
- 2周目以降: 記憶したコースに基づき、**毎周回タイムを更新**する学習レーシング
- スタートの「垂直な2本線」をゲートとして自動検出 → ラップタイム計測・ベスト記録
- ストックファームウェアを **Pybricks** に書き換えて、SPIKE の限界性能を引き出す

> 開発者向けの運用規約は **AGENTS.md** を参照。コード変更時は必ず
> `python _selftest.py` を通すこと。

## 1. ハードウェア構成

### 配線（デフォルト）

| ポート | 機器 |
|---|---|
| A | 左モーター（ラージ） |
| B | 右モーター（ラージ） |
| C | 左カラーセンサー |
| D | 右カラーセンサー |

### 機体ビルドのポイント

- **駆動**: ラージモーター ×2 を最大径ホイール（約 88.8mm）に直結。軽量化優先
  （最高速だけでなく**加速度・実効速度・制御安定性**でラージが優位。詳細は開発ログ参照）
- **センサー**: 2個のカラーセンサーで**ラインを挟む**配置（間隔 = ライン幅の 1.5〜2 倍程度）
- **ブーム**: センサーをホイール軸の前方 10〜15cm に、ガタなく剛結（曲線の先読みになる）
- **重心**: 駆動軸の真上・低く。後部は摩擦の小さいスキッド/キャスター
- **高さ**: センサー底面は床から 5〜10mm（反射が安定する位置で固定）

> ホイール**円周**は実測推奨: 床に印を付けてホイールを10回転させ、移動距離 ÷ 10
> を `main.py` の `WHEEL_D_CM` に設定（SPIKE Prime 大タイヤ φ8.88cm → 円周 27.9cm）。
> ⚠ 直径と間違えないこと（π 倍の速度・距離・κ 誤差になる）。

## 3. 起動時の自動セットアップ

起動すると以下が**自動で**実行されます（人間の作業はほぼ不要）:

| ステップ | 内容 |
|---|---|
| 1. デバイス接続チェック | 4ポートの接続を確認。未接続があれば赤字で警告 |
| 2. ベンチマーク | ループレートとカラーセンサーの実効更新レートを表示 |
| 3. ジャイロキャリブレーション | 静止1秒でバイアス測定 |
| 4. **符号自動テスト** | 前進/後退・左右旋回を0.3秒ずつ実行し、**モーター方向(CMD_FLIP)とジャイロ符号(SIGN_GYRO)を自動判定**。手動調整不要（判定不能時のみ WARN 表示） |
| 5. **ホイール円周キャリブレーション** | その場旋回（0.8秒×2方向）で円周を実測し `WMUL/SMUL` を±15%クランプで自動更新。実測は `wheel cal: C=xx.xcm` で表示 |
| 6. スタート待ち | 中央ボタン or 10秒で自動スタート |

> 符号テスト中はロボットが動きます。**周囲に物を置かないでください。**

## 4. 操作方法

| 操作 | 内容 |
|---|---|
| **中央ボタン** | スタート（10秒待つと自動スタート） |
| **左ボタン** | ダンプモード切替（周回終了時に直近ラップのテレメトリを USB コンソールへ出力） |
| **右ボタン** | 現在の設定・統計を表示 |
| **中央+左+右 同時** | プログラム停止 |

- ライトマトリクス: 走行中は経過秒×10、ベスト更新時はベストタイム×10 を表示
- ステータスライト: 緑=走行中、橙=ゲート探索、赤=異常。ベスト更新でブザー2音
- **ベスト更新ラップは自動でテレメトリダンプ**（`AUTO_DUMP_BEST`）

## 5. 学習システムの仕組み

### 1周目（エクスプローララン）
- 速度 35cm/s 固定で完走し、弧長 s 基準で以下を記録
  - **曲率マップ** κ(s)（ジャイロ ÷ 速度を積算、i16 クランプ付き）
  - **誤差プロファイル** e(s)（2センサー差動の正規化誤差）
  - **ゲート間隔**（2本線の白ギャップを学習 → 次周からの検証に使用）
  - ヒストグラムによる白/黒キャリブレーション（ライン極性自動判定）
- ジャイロ減衰はフル GYRO（安定性優先。κマップの微妙な歪みは ILC が補正）

### 2周目以降（学習レーシング）
| 機構 | 内容 |
|---|---|
| 曲率フィードフォワード | `st = κ·v·B/2`（ステアリング=速度差の半分。幾何学的先行） |
| ルックアヘッド | 前方30cmの最大曲率から `v = √(a_lat/κ)` で**先読み減速** |
| **速度正規化 ILC** | `FF(s) += α·e(s)·(100/v)` — **速度に依存しない FF** として収束が速く、速度プロファイル変更と干渉しない。α は誤差に応じて 0.025〜0.06 に適応 |
| 速度プロファイル | 横加速度限界 + 加減速制約で毎周回再最適化。成長は**ベスト相当ラップのみ**（移動中央値で判定） |
| **ベストラップ全体スナップショット** | ff+vmax+KP/KD+A_LAT を保存し、**2ラップ連続悪化で全体ロールバック** |
| **局所探索（E-greedy）** | 5ラップごとに直線区間の vmax を +10% 試行。改善時のみ採用（ローカルミニマム脱出） |
| **セクション局所ゲイン** | 100cm ごとの区間で KP/KD 倍率を自動学習（発振区間は KP減/KD増、追従遅れ区間は KP増） |
| グリップ学習 | p99 誤差（単発ノイズ非依存）から A_LAT を自動調整。**スリップ検出**（指令ω vs 実測ω）でも抑制 |
| ゲイン自動調整 | 発振指数（tick内計測）・RMS誤差から KP/KD を微調整 |
| 電圧補償 | バッテリー電圧低下による速度劣化を補正 |

### ゲート検出（ラップ境界）
「両センサ同時黒」のイベントで「白→黒→白→黒→白」パターン + 距離検証で
2本の垂直ラインを検出:

- **両センサ同時黒（AND）方式**: ゲートの垂直2本線はセンサを両方暗くするが、
  主ライン（センサ間隔より狭い）は片側しか暗くしないため、蛇行による誤検出を排除
- 1周目: デフォルト範囲（間隔 3〜100cm）で検出 → **間隔を学習**
- 2周目以降: **学習済み間隔 ±50%** で検証 + **位置窓**（`track_len±100cm`）内のみで検出
- ゲート手前 30cm は 45cm/s に自動減速（読み飛ばし防止）
- **読み飛ばし時**: 低速探索モードに切り替え、次のゲートで再検出
  （そのラップは学習スキップ。マップの座標系は壊さない）
- **通過時刻はエッジ補間**でサブミリ秒精度のラップタイムを記録

## 6. 初回セットアップ手順

1. 配線と機体を確認し、ライン上でロボットをゲート手前に置く
2. 起動（自動セットアップが走る。WARN が出たら指示に従う）
3. 中央ボタンでスタート
4. 1周走らせてゲートを通過 → 2周目以降でタイムが伸びれば OK

> 符号系（SIGN_ST / SIGN_GYRO / CMD_FLIP）は自動判定されますが、判定不能な
> WARN が出た場合は `main.py` の SIGN_* を手動で調整してください。
> どちらの場合も最初は必ず低速（`V_LAP1` はそのまま）で確認。

## 7. チューニング

### 速度を上げる順序

1. **MOTOR_MAX** を実測値に設定（ホイールを浮かせて起動ログの `vavg` を確認）
2. `A_LAT` 初期値を上げる（グリップに自信があれば 250〜300。学習でも自動調整される）
3. 直線の `v_glob_max` は良好ラップ（誤差13%未満・低発振・ベスト相当）で +4cm/s/周 ずつ成長する（上限 `MOTOR_MAX`）。`vmax` プロファイル自体はカーブ曲率で自動制限

### 実機で最初に確認すること

- **微分項とブーム長（最重要）**: センサーが旋回中心から前方 L cm にある機体は、
  旋回中のブーム振れが `de` に強く現れ、**D 項が旋回を増強する正帰還**を起こして
  発振する（L=16cm で確認。閉ループsimでも KD=30→発振、KD=0→安定）。L≧10cm では
  **`KD=0` を推奨**（デフォルト）。L≦5cm にブームを短縮した場合のみ `KD=10〜20` に
  戻せる。1次ローパス `de_f=(de_f·5+de)//6` はノイズ対策として実装済み。
- **スリップ検出の過検出**: カーブで `A_LAT` が急落する（ログの `a_lat` が毎周
  数%ずつ減る）場合は `SLIP_THRESH` を 25 → 35 に上げる。
- **曲率FFの符号**: カーブの入りで外側に膨らむ（FF不足）／内側に切れ込む（FF過大）を
  確認。FF定数 `8000` は幾何学的に導出済み（トレッド `TRACK_B_CM`=16cm 前提）だが、
  実測のトレッドと合わせて検証すること。
- **ゲート検出**: マッチャーは「両センサ同時黒」で駆動するため、主ラインの横断では
  誤検出しない。ゲートの2本線が主ラインより**薄い**場合（反射率差が小さい）は
  `line_both` の閾値 500 を下げる必要がある場合がある。

### 発振するとき

- **`KD` は 0 を基本に**（ブーム D 項正帰還。L≧10cm では KD を上げると悪化する）
- `KP` を下げる（初期 90 → 60 程度。適応学習がラップ単位で自動調整もする）
- センサーブームを短くする・剛性を上げる（L≦5cm なら KD を戻せる）
- `BOOM_K` を調整（0 で無効、500 で強め）
- セクション局所ゲインが自動で補正する（ラップ3以降）

### 収束が遅いとき

- `ILC_ALPHA_HI/MID/LO` を上げる（初期 0.06/0.04/0.025 → 0.08 等。暴れにくいことを確認しながら）
- ルックアヘッド `LA_BINS` を増やす（30cm → 40cm で減速開始が早くなる）

### 速度成長の仕組み（要確認）

- `V_MAX_INIT`（初期 50cm/s、ラップ2の控えめな出発点。ブーム16cm だと高速度は安定
  余裕を失いやすいため従来65→50）から、良好ラップ
  （誤差13%未満・低発振・ベスト相当）で +4cm/s/周ずつ成長し `MOTOR_MAX` で頭打ち
- ラップ1のエクスプローラは 35cm/s 固定。ジャイロ減衰はフル GYRO
  （ラップ1の半減を廃止。安定性優先で κマップの歪みは ILC が補正）
  （純減衰がカーブと戦って κ マップが歪む問題の対策）
- 速度は曲率プロファイル（A_LAT 制限）とルックアヘッドでも制限されるため、
  カーブの突入速度は幾何的に安全側に保たれる

### 探索の頻度

- `EXPLORE_EVERY`（デフォルト5ラップ間隔）で直線区間の速度を試す。
  改善しなければ自動で戻るので放置して OK

## 8. オフライン解析（PC）

1. ベスト更新ラップは**自動ダンプ**。手動でも左ボタンでダンプモード切替
2. USB コンソールの出力を `dump.csv` に保存（Pybricks Code のコンソールからコピー）
3. 解析:

```bash
python analyze_laps.py dump.csv            # レポート
python analyze_laps.py dump.csv --plot     # グラフ(PNG)出力 (matplotlib)
python analyze_laps.py dump.csv --report report.txt
```

- 軌跡再構成（オドメトリ+ジャイロ）、曲率プロファイル、セグメント分類
- 実測最大横加速度 → `A_LAT` 推奨値
- ラップタイム表（ベストマーク付き）

サンプル: `python analyze_laps.py sample_dump.csv`

## 9. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 起動時に NOT CONNECTED | 配線を確認。ポート設定（PORT_*）と実配線を突き合わせる |
| 符号テストで WARN | 床が傾斜/滑りやすい可能性。平らな場所で再起動。それでも駄目なら SIGN_* 手動設定 |
| ゲートを見つけられない | センサー高さ・間隔を確認。白/黒が両方見える場所から開始 |
| タイムが毎周悪化 | ベストラップ状態への自動ロールバックが働く（2ラップ連続悪化で発動） |
| カーブで飛び出す | `A_LAT` を下げる・`LA_BINS` を増やす・`KP` を下げる |
| 直線で蛇行 | `KD` が 0 であることを確認（ブームあり機体は KD を上げると悪化）。`BOOM_K` を増やす・`GYRO` を上げる |
| ゲートを読み飛ばす | 自動で低速探索→次周で回復。頻発するなら `GATE_DIP_CM` を広げる |
| ゲート通過後に TypeError（bytearray item assignment）で落ちる | Pybricks の MicroPython は `ba[:] = ...` のスライス代入不可。v1.1.0 で要素ループ（`ba_clear`/`ba_copy`）に置換済み。カスタムコードではスライス代入を使わない |
| コンソールが出ない | USB 接続を確認。Bluetooth 経由はダンプに時間がかかる |

## 10. 性能・メモリ

- MCU: STM32F413VG（Cortex-M4F 100MHz / 1.5MB Flash / **320KB RAM**）
- 制御ループ: ネイティブコード化（`@micropython.native`）で数百Hz〜1kHz 目標
  （起動時に実測値を表示。センサー実効更新レートも表示）
- 学習テーブル: 曲率/FF/速度プロファイル/ベストスナップショット/セクション統計
  ≈ 55KB + ラップログ 49KB（RAM上でラップ間継承）
- ループ内は整数演算中心・動的確保ゼロ設計（GC ストレス最小化）
- ラップ境界の学習処理はネイティブ化で ~30ms（100cm/s で 3cm の無制御）
