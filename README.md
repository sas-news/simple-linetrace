# SPIKE Prime ライントレーサー "LINE RACER SLIM" v2.0

LEGO SPIKE Prime（基本セット 45678 + 拡張セット 45681）で作る、
**無限周回ライントレースのベストタイム記録機**。

**フィールド**: 白いフィールド上に、ランダムな曲線が一周した黒いラインと、
進行方向に垂直な**マーカー線**（スタート/ゴール）を1本引く。
障害物・ミッションはなし。いかに速く正確にラインを周回し続けるかだけを競う。

- 起動時の**自動セットアップ**（配線チェック・ジャイロバイアス測定）
- 両センサー同時暗でマーカー線を検出 → ラップタイム計測・ベスト記録
- 実測キャリブレーションに基づく堅牢なシンプル制御
  （v1.x の2本線ゲート・符号自動テスト・複雑な学習系は廃止。開発経緯は MEASURE_NOTES.md）
- ストックファームウェアを **Pybricks** に書き換えて、SPIKE の限界性能を引き出す

> 開発者向けの運用規約は **AGENTS.md** を参照。コード変更時は必ず
> `python _selftest.py` と `python _smoke_test.py` を通すこと。

## 1. ハードウェア構成

### 配線（実測確定）

| ポート | 機器 |
|---|---|
| A | 左モーター（ラージ） |
| E | 右モーター（ラージ） |
| B | 左カラーセンサー |
| F | 右カラーセンサー |

### 機体ビルドのポイント

- **駆動**: ラージモーター ×2 を大径ホイールに直結。軽量化優先
- **センサー**: 2個のカラーセンサーで**ラインを挟む**配置（間隔 = ライン幅の 1.5〜2 倍程度）
- **ブーム**: センサーをホイール軸の前方に、ガタなく剛結（曲線の先読みになる）
- **重心**: 駆動軸の真上・低く。後部は摩擦の小さいスキッド/キャスター
- **高さ**: センサー底面は床から 5〜10mm（反射が安定する位置で固定）

> 実測確定値（main.py 反映済み）: ホイール**円周 27.6cm**、トレッド **16cm**。
> 円周を変えた場合は `main.py` の `WHEEL_C_CM` と `WMUL`/`SMUL` を更新
> （`WMUL = 36000/円周`、`SMUL = 円周*10000/360`）。
> ⚠ 直径と間違えないこと（π 倍の速度・距離誤差になる）。

## 3. 起動時の自動セットアップ

起動すると以下が**自動で**実行されます（人間の作業はほぼ不要）:

| ステップ | 内容 |
|---|---|
| 1. デバイス接続チェック | 4ポートの接続を確認。未接続があれば `NOT CONNECTED` を表示 |
| 2. ジャイロバイアス測定 | 静止1.2秒でバイアス測定（±5deg/s でクランプ） |
| 3. スタート待ち | 中央ボタン or 10秒で自動スタート |

> キャリブレーション中は**完全に静止**させること。動かすとバイアスが大きくずれる。
> 符号系（CMD_FLIP / SIGN_GYRO_CUR / SIGN_ST）と反射光キャリブレーションは
> **実測値に固定**済み（起動時テストは行わない）。機体を変えた場合のみ
> `measure_robot.py` で再計測して `main.py` の定数を更新する。

## 4. 操作方法

| 操作 | 内容 |
|---|---|
| **中央ボタン** | スタート（10秒待つと自動スタート） |
| **左ボタン** | ダンプモード切替（周回終了時に直近ラップのテレメトリを USB コンソールへ出力） |
| **右ボタン** | 現在の設定・統計を表示 |
| **中央+左+右 同時** | プログラム停止 |

- ライトマトリクス: 走行中は経過秒×10、ベスト更新時はベストタイム×10 を表示
- ステータスライト: 緑=走行中、橙=マーカー探索、赤=異常。ベスト更新でブザー2音
- **ベスト更新ラップは自動でテレメトリダンプ**（`AUTO_DUMP_BEST`）

## 5. 制御の仕組み

### ライン追従

- 左右カラーセンサーの反射を実測キャリブ（L: 白96/黒13, R: 白95/黒12）で
  0..1000 に正規化し、差動誤差 `e` を計算
- ステアリング `st = KP·e_fil + GYRO·wz_d`（e_fil は1次ローパス済み誤差）
- **ジャイロ減衰はウォッシュアウト式**: 基準 `wz_base` をゆっくり追従させ、
  `wz_d = wz_f - wz_base` だけで減衰 → バイアス変動に騙されない
  （この機体のジャイロはバイアスが不安定。詳細は MEASURE_NOTES.md）
- 速度は誤差 `|e_fil|` で自動減速（V_MIN まで）+ 加減速ランプ + バッテリー電圧補償
- 1周目は `V_EXPLORE`（30cm/s）の計測走行でコース全長 `track_len` を学習、
  2周目以降は `V_CRUISE` 巡航

### マーカー検出（ラップ境界）

コース上1箇所の**単一横断マーカー線**を「両センサ同時暗」で検出:

- 主ラインはセンサーで挟んで追従するため両方同時には暗くならない → 誤検出を排除
- マーカー幅 0.5〜10cm 以外の暗区間は拒否、検出後 40cm は再アームしない
- 1周目: 検出位置をそのまま採用し `track_len`（コース全長）を学習
- 2周目以降: `track_len ±60cm` の位置窓内のみ受理 + **オドメトリで強制クローズ**
  （マーカーを読み飛ばしても `s_cm >= track_len` で必ずラップを閉じる）
- **通過時刻はエッジ補間**でサブティック精度のラップタイムを記録

### 学習FF（ILC）とレーシング（実装済み・フラグで無効化中）

- **ILC**: 各周の追従誤差を 2cm ビン毎に学習し、v=100cm/s 基準の
  ステアリングFFとして保持 → 次周から `st += ff[s]·v//100` で事前に曲線に対応。
  `ff_armed`（前ラップの rms_e ≦ 250）成立後のみ適用。
- **レーシング**: 実行ステアリングからビン毎の速度上限 `vmax` を学習し、
  ルックアヘッドで事前減速。外輪を高速・内輪を落とす `race_wheels` 則。
  マーカー前後 ±10cm は `V_MARK` に自動減速。

> 現状はベース制御の隔離確認のため `ILC_ALPHA = 0` / `RACE_MODE = False`。
> 実機でベースが安定したら `ILC_ALPHA = 20`、`RACE_MODE = True` に戻す
> （main.py の該当コメント参照）。

## 6. 初回セットアップ手順

1. 配線と機体を確認し、ライン上でロボットを**マーカー線の直前**に置く
2. 起動（自動セットアップが走る。静止を維持）
3. 中央ボタンでスタート → マーカー探索で最初のマーカーを通過
4. 1周走らせてマーカー通過 → `track len (lap1)` が表示されたら OK

## 7. チューニング

### 速度を上げる順序

1. モーター実測最高速を確認（本機は 77cm/s 実測。`V_CRUISE` は余裕を見て低めに）
2. `V_CRUISE` を上げる（19Hz のセンサー実効レートとブーム輸送遅延の兼ね合い。
   上げすぎると検出→ホイール到達の遅れ距離が増え、急なラインロストが増える）
3. `RACE_MODE = True` で速度計画を有効化（`V_RACE_MAX` が上限。`A_LAT_MAX` で
   カーブ突入速度を制限）

### 実機で最初に確認すること

- **ジャイロバイアス**: 起動ログの `calib: bias=` が ±5000 に張り付いていたら
  静止不足。平らな場所で再起動。
- **微分は KD=0 固定**: センサーブームの振れが D 項を正帰還させて発振するため。
  ブームを極短（≦5cm）にした場合のみ戻せる。実効 ~19Hz のセンサーでは
  微分の恩恵も薄い。
- **マーカー読み飛ばし**: 高速時に `both_dark` を取りこぼす場合は `V_MARK` を
  下げる、またはマーカー線を太くする（実測 1.8cm。`MARK_MAX` 内であること）

### 発振するとき

- `KP` を下げる（初期 35）
- `GYRO` を下げる（初期 650。ジャイロが不安定な機体では 0 も視野）
- センサーブームを短くする・剛性を上げる
- 19Hz センサーの跳び・バウンド対策として `e_fil` ローパス係数を強める

### 収束が遅いとき

- `ILC_ALPHA` を上げる（推奨復帰値 20）
- ルックアヘッド `LA_BINS` を増やす（15 → 減速開始が早くなる）

## 8. オフライン解析（PC）

1. ベスト更新ラップは**自動ダンプ**。手動でも左ボタンでダンプモード切替
2. USB コンソールの出力を `dump.csv` に保存（Pybricks Code のコンソールからコピー）
3. 解析:

```bash
python analyze_laps.py dump.csv            # レポート
python analyze_laps.py dump.csv --plot     # グラフ(PNG)出力 (matplotlib)
python analyze_laps.py dump.csv --report report.txt
```

- 軌跡再構成（オドメトリ+ジャイロ）、曲率プロファイル、セグメント分類
- 実測最大横加速度 → `A_LAT` 推奨値
- ラップタイム表（ベストマーク付き）

サンプル: `python analyze_laps.py sample_dump.csv`

## 9. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 起動時に NOT CONNECTED | 配線を確認。ポート設定（A/E/B/F）と実配線を突き合わせる |
| `calib: bias=` が ±5000 張り付き | キャリブ中に動いた/振動。完全静止で再起動 |
| `marker not found` が出る | ロボットをライン上・マーカー手前に置く。センサー高さ・間隔を確認 |
| 1周目が実際の2倍前後の長さで記録される | 1周目にマーカーを読み飛ばした → `track_len` が2倍で学習された。再起動してマーカー直前から開始 |
| 発進直後に蛇行・逆走 | 符号系が機体と不一致。`measure_robot.py` で再計測し CMD_FLIP/SIGN_GYRO_CUR を更新 |
| 走行中にプルプル | `KP`/`GYRO` を下げる。バウンド誤読なら `e_fil` 係数を強める |
| カーブで飛び出す | `V_CRUISE` を下げる。レーシング中は `A_LAT_MAX` を下げる・`LA_BINS` を増やす |
| 高速でマーカーを読み飛ばす | `V_MARK` を下げる（~19Hz のセンサー更新周期で幅を跨げる速度にする）。なお読み飛ばしてもオドメトリでラップは閉じる |
| TypeError（bytearray item assignment）で落ちる | Pybricks の MicroPython は `ba[:] = ...` のスライス代入不可。`ba_clear`/`ba_copy` の要素ループを使う |
| コンソールが出ない | USB 接続を確認。Bluetooth 経由はダンプに時間がかかる |

## 10. 性能・メモリ

- MCU: STM32F413VG（Cortex-M4F 100MHz / 1.5MB Flash / **320KB RAM**）
- 制御ループ: ネイティブコード化（`@micropython.native`）。
  カラーセンサーの実効更新レートは **~19Hz**（実測。MEASURE_NOTES.md 参照）
- テーブル: ラップログ 48KB + 学習FF/速度計画 ~16.5KB（RAM上でラップ間継承）
- ループ内は整数演算中心・動的確保ゼロ設計（GC ストレス最小化）
- ラップ境界の学習処理は finalize_lap のネイティブ化で短時間に抑える
  （その間モーターは明示停止）
